# Intent: รายงานจุดน้ำท่วมจากคนในพื้นที่

> สถานะ: ร่าง (2026-09-30) จากการ grill รอบแรก
> Q1 และ Q2 เจ้าของฟีเจอร์เลือกเอง ข้ออื่นใช้คำตอบที่ Claude แนะนำ เจ้าของฟีเจอร์ตอบว่า "เอาตามแนะนำให้หมดเลย"

## Problem

ตอนนี้ "น้ำท่วมไหม" มีแค่ระดับน้ำจากสถานีวัดในคลอง (`GET /districts/:id`) แต่คนที่จะออกจากบ้านอยากรู้ว่า**ถนนหรือซอยที่จะผ่านมีน้ำท่วมหรือเปล่า และลึกแค่ไหน** ข้อมูลสถานีตอบคำถามนี้ไม่ได้ เพราะ

- สถานีมีน้อย (บางเขตไม่มีเลย) และวัดระดับน้ำในคลอง ไม่ใช่บนถนน
- คนที่เห็นน้ำท่วมกับตาไม่มีช่องทางบอกคนอื่นในแอป ข้อมูลจึงกระจายอยู่ในแชตกลุ่ม ซึ่งค้นยาก ไม่รู้ว่าเก่าแค่ไหน และมีรายงานซ้ำกันเยอะ

## Proposed outcome

คนในพื้นที่ส่งรายงานได้ 4 ข้อมูล คือ **เขต จุดสังเกต ความลึก และเวลาที่เห็น** รายงานขึ้นให้ทุกคนเห็นทันทีคู่กับข้อมูลสถานีของเขตนั้น

พฤติกรรมที่ตกลงกันแล้ว

| เรื่อง | ข้อตกลง |
| --- | --- |
| การเผยแพร่ | ขึ้นทันที ไม่มีคนตรวจก่อน ใช้กฎอัตโนมัติกรองแทน (Q1) ทุกรายงานต้องติดป้ายว่า**ผู้ใช้รายงาน ยังไม่ยืนยัน ไม่ใช่ประกาศเตือนภัยทางการ** |
| ตัวตนคนรายงาน | ไม่บังคับ ใส่เบอร์โทรได้ถ้าต้องการ เบอร์เก็บไว้ในระบบเท่านั้น ไม่แสดงใน API สาธารณะ และห้ามลง log ทุกรูปแบบ ให้ log ด้วย report ID แทน (Q2) |
| เขต | ต้องเป็นหนึ่งใน 12 เขตใน `src/districts.ts` อ้างด้วย id |

| ความลึก | จำนวนเต็ม หน่วยเซนติเมตร ช่วง 0–300 ซม. |

| รายงานซ้ำ | เขตเดียวกันและจุดสังเกตเดียวกัน (หลัง normalize ข้อความ) ภายใน 1 ชั่วโมง รวมเป็นรายการเดียว และนับจำนวนคนที่ยืนยัน |
| การหมดอายุ | ไม่แสดงรายงานที่เก่ากว่า 6 ชั่วโมงนับจากเวลาที่เห็น |
| จำกัดจำนวนครั้ง | ไม่เกิน 5 รายงานต่อ 10 นาที **นับตาม IP เสมอ** ถ้ามีเบอร์โทรให้ใช้นับเป็นเงื่อนไขเสริมได้ แต่ห้ามใช้แทนการนับตาม IP |

**วัดผลยังไง**

- ส่งรายงานที่ถูกต้องแล้วเห็นใน `GET /districts/:id` ได้ทันทีใน request ถัดไป
- ทุกกฎในตารางด้านบนมี test ครอบ (ข้อมูลผิดโดนปฏิเสธ รายงานซ้ำถูกรวม รายงานหมดอายุหายไป ส่งเกินจำนวนได้ 429)
- ไม่มีเบอร์โทรใน response ใดๆ และไม่มีใน log (ตรวจได้ด้วย test และ review)
- ทุก response ที่มีรายงานต้องมีข้อความว่าผู้ใช้รายงาน ไม่ใช่ประกาศเตือนภัยทางการ
- `npm test` และ `npm run lint` ผ่าน และ endpoint เดิมยังตอบเหมือนเดิม

## Constraints

ทุกข้อใน skill `security-baseline` (`.claude/skills/security-baseline/SKILL.md`) ใช้กับฟีเจอร์นี้ทั้งหมด

**ความปลอดภัยของคนใช้**
- ทุก response ต้องมี `NOTICE` เหมือนเดิม (ข้อมูลเพื่อการเรียน ไม่ใช่ประกาศเตือนภัยทางการ) และทุกรายงานต้องระบุว่า "ผู้ใช้รายงาน ยังไม่ยืนยัน ไม่ใช่ประกาศเตือนภัยทางการ"
- ตรวจข้อมูลทุกช่องที่ API handler อย่าเชื่อข้อมูลที่มาจาก client
- **ห้ามส่งหรือลบข้อมูลในระบบรายงานน้ำท่วมจริง** เช่น `flood-api.rooptanjai.com` ใช้ได้แค่ GET ทั้งในโค้ด ใน test และตอนทดลองมือ

**ข้อมูลส่วนบุคคล (PDPA)**
- เบอร์โทร ชื่อ และที่อยู่ที่ระบุตัวคนได้เป็นข้อมูลส่วนบุคคล ต้องเก็บเท่าที่จำเป็น ห้ามออก API สาธารณะ และห้ามลง log (ให้ log ด้วย ID แทน)
- ห้ามใส่เบอร์จริงใน test, fixture หรือ commit

**งบและเทคโนโลยี**
- ไม่ใช้บริการภายนอกที่เสียเงิน และไม่เพิ่ม runtime dependency (ตอนนี้ repo มีแค่ devDependencies)
- รอบแรกเก็บรายงานในหน่วยความจำ (in-memory) ได้ ยอมรับว่ารายงานหายเมื่อ restart server

**สิ่งที่ห้ามแตะ**
- `data/stations.json` และความหมายของข้อมูลสถานี
- รูปแบบ response ของ `GET /districts` และ `GET /districts/:id` ที่มีอยู่แล้ว เพิ่ม field ได้ แต่ห้ามเปลี่ยนหรือลบ field เดิม
- กติกาหน่วยเซนติเมตรจำนวนเต็ม และเวลาเก็บเป็น UTC
- แนวทาง `handle()` ใน `src/app.ts` ต้องไม่ผูกกับ `node:http` และรับ `now` ผ่าน `ctx` เพื่อให้ test ควบคุมเวลาได้
