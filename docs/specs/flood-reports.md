# Spec: รายงานจุดน้ำท่วมจากคนในพื้นที่

> Intent: docs/intent/flood-reports.md · Skills applied: security-baseline

## Requirements

| ID | Requirement | Acceptance criteria (testable) |
| -- | ----------- | ------------------------------ |
| RPT-REQ-001 | ส่งรายงานได้ | `POST /reports` รับ `{ districtId, landmark, depthCm, seenAt, phone? }` ตอบ 201 พร้อม `id`, `severity`, `confirmations: 1` |
| RPT-REQ-002 | ระดับความรุนแรงจากความลึก | 1–10 ซม. = 1 น้ำขัง · 11–30 = 2 รถเล็กผ่านยาก · 31–50 = 3 รถเล็กผ่านไม่ได้ · มากกว่า 50 = 4 อันตราย |
| RPT-REQ-003 | ตรวจข้อมูลที่ส่งมา | `districtId` ต้องมีอยู่จริง · `landmark` 2–100 ตัวอักษรหลังตัดช่องว่าง · `depthCm` เป็นจำนวนเต็ม 1–300 · `seenAt` ไม่อยู่ในอนาคตเกิน 5 นาที และไม่เก่ากว่า 6 ชั่วโมง · `phone` (ถ้ามี) เป็นเบอร์มือถือไทย 10 หลักขึ้นต้นด้วย 06, 08 หรือ 09 · ผิดข้อใดได้ 400 |
| RPT-REQ-004 | รวมรายงานซ้ำ | เขตเดียวกัน และจุดสังเกตเดียวกัน (ไม่สนตัวพิมพ์เล็กใหญ่และช่องว่าง) ภายใน 2 ชั่วโมงนับจากการยืนยันล่าสุด ให้แก้รายงานเดิม: ความลึกเป็นค่าล่าสุด `confirmations` เพิ่มหนึ่ง ตอบ 200 และ `merged: true` |
| RPT-REQ-005 | รายงานหมดอายุ | รายงานที่ยืนยันล่าสุดเกิน 6 ชั่วโมงไม่แสดงใน `GET /districts/:id/reports` แต่ยังเก็บไว้ |
| RPT-REQ-006 | ดูรายงานของเขต | `GET /districts/:id/reports` คืนรายงานที่ยังไม่หมดอายุ เรียงจากรุนแรงมากไปน้อย แล้วจากยืนยันล่าสุดไปเก่า เวลาแสดงเป็นเวลากรุงเทพฯ |
| RPT-REQ-007 | จำกัดจำนวนรายงาน | ส่งรายงานได้ไม่เกิน 5 ครั้งต่อ IP ใน 10 นาที ครั้งที่ 6 ได้ 429 |
| RPT-REQ-008 | เบอร์โทรไม่หลุด | `phone` ไม่ปรากฏใน response ใดๆ และไม่ถูกเขียนลง log |
| RPT-REQ-009 | บอกว่าไม่ใช่ประกาศทางการ | ทุก response ของรายงานมี `notice` ว่าเป็นข้อมูลจากผู้ใช้ ไม่ใช่ประกาศเตือนภัยทางการ |

## Design

- **Data model:** `Report = { id, districtId, landmark, landmarkKey, depthCm, severity, seenAt, createdAt, lastConfirmedAt, confirmations, phone? }` เก็บในหน่วยความจำที่ `src/reports.ts` (class `ReportStore`)
- **landmarkKey:** ตัดช่องว่างหัวท้าย ยุบช่องว่างซ้อน และเป็นตัวพิมพ์เล็ก ใช้จับคู่รายงานซ้ำ
- **Logic:** `severityFor(depthCm)`, `validateReport(input, now)`, `ReportStore.submit(input, now)`, `ReportStore.active(districtId, now)` ทุกฟังก์ชันรับ `now` เป็นพารามิเตอร์
- **API:** `POST /reports` และ `GET /districts/:id/reports` ใน `src/app.ts`
- **Rate limit:** `src/rate-limit.ts` นับครั้งต่อ IP ในหน้าต่างเวลา 10 นาที
- **ไฟล์ที่แตะ:** `src/reports.ts` (ใหม่), `src/rate-limit.ts` (ใหม่), `src/app.ts`, `src/server.ts` (ส่ง IP), tests

## Edge cases

1. ความลึก 10 กับ 11, 30 กับ 31, 50 กับ 51 ซม. อยู่คนละระดับ
2. จุดสังเกต "ซอยลาดพร้าว 71" กับ "  ซอยลาดพร้าว  71 " เป็นจุดเดียวกัน
3. รายงานซ้ำตอน 2 ชั่วโมงพอดีหลังยืนยันล่าสุด ยังรวมกัน ถ้าเกินแม้หนึ่งนาทีเป็นรายงานใหม่
4. รายงานซ้ำที่ความลึกลดลง ใช้ค่าล่าสุด ไม่ใช่ค่าสูงสุด
5. จุดสังเกตเดียวกันคนละเขต ไม่ใช่รายงานซ้ำ
6. รายงานที่หมดอายุแล้วมีคนรายงานจุดเดิมอีก เป็นรายงานใหม่
7. `seenAt` เป็นสตริงที่แปลงเป็นวันที่ไม่ได้ ได้ 400
8. ไม่ส่ง `phone` มาก็รายงานได้

## Out of scope

- แนบรูป และพิกัด GPS
- หน้าจัดการสำหรับเจ้าหน้าที่ และการลบหรือซ่อนรายงาน
- การแจ้งเตือนผู้ใช้
- เชื่อมข้อมูลระดับน้ำจริง (เป็นแบบฝึกหลังคลาส)

## Risks

- ถ้ารวมรายงานผิด คนจะเห็นข้อมูลเก่าหรือเห็นจุดเดียวซ้ำหลายครั้ง
- ถ้าเบอร์โทรหลุดลง log หรือ response เป็นการรั่วไหลของข้อมูลส่วนบุคคล
- ถ้าไม่มี rate limit คนเดียวสร้างรายงานปลอมได้เป็นร้อย
